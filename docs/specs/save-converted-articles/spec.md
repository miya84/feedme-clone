# 변환한 글 저장과 저장한 글 목록

로그인한 사용자가 변환한 글을 "저장"해 두고, 저장한 글 목록에서 다시 열어 보고 내보내고 삭제할 수 있게 한다.

Linked sources:

- [GLOSSARY.md](../../../GLOSSARY.md) — 변환한 글, 저장한 글, 저장한 글 목록의 뜻을 지배한다. 이 스펙은 정의를 다시 적지 않는다.
- [url-to-markdown 스펙](../url-to-markdown/spec.md) — 변환 화면, 내보내기 동작, UI 문구를 지배한다. 그 스펙의 "변환 결과는 서버에 저장하지 않는다" 가정과 "변환 이력·계정·서버 저장" 범위 밖 항목은 이 스펙이 **저장한 글에 한해** 대체한다. 저장 버튼을 누르지 않은 변환 결과는 여전히 서버에 남지 않는다.
- [prototype.html](../url-to-markdown/prototype.html) — 변환 화면의 승인된 모습을 지배한다. 저장 버튼, 목록, 상세 화면은 이 프로토타입에 없다.
- [ui-composition](../../decisions/ui-composition.md) — 새 화면(목록, 상세, 빈 상태, 삭제 확인)의 구성 체계를 지배한다.
- [dependency-versions](../../decisions/dependency-versions.md) — 새 의존성이 필요할 때의 버전 정책을 지배한다.

## 사용자에게 보이는 결과

1. **저장** — 변환이 끝난 결과 영역의 내보내기 버튼들 옆에 `저장` 버튼이 보인다. 로그인한 사용자가 누르면 그 변환한 글이 저장한 글이 되고 저장됐음을 알린다.
2. **같은 주소를 다시 저장** — 이미 저장한 주소를 다시 저장하면 항목을 새로 만들지 않고 기존 항목을 방금 변환한 내용으로 갱신하며, 갱신했음을 알린다.
3. **비로그인 저장 시도** — 로그인하지 않은 사용자가 `저장`을 누르면 "로그인하면 저장할 수 있습니다"라는 안내와 로그인으로 가는 링크가 보인다. 변환 결과는 화면에 그대로 남고, 복사·다운로드·LLM으로 열기는 계속 쓸 수 있다.
4. **목록 진입** — 메인 화면 상단의 `설정` 옆에 `저장한 글` 링크가 있다. 누르면 저장한 글 목록(`/saved`)이 열린다.
5. **저장한 글 목록** — 본인이 저장한 글이 최근 저장한 순서로 보이고, 각 항목에 제목, 원문 도메인, 저장한 날짜가 보인다. 저장한 글이 없으면 빈 상태 안내가 보이고 변환 화면으로 가는 길이 있다.
6. **다시 보기** — 목록의 항목을 누르면 상세 화면이 열려, 변환 결과 영역과 같은 헤더(제목, 저자(있을 때만), 원문 도메인)와 렌더링된 Markdown 본문이 보인다. 복사하기, .md 다운로드, ChatGPT로 열기, Claude로 열기, 프롬프트 선택(1회용, 저장하지 않음)을 변환 화면과 똑같이 쓸 수 있다. 목록으로 돌아가는 길이 있다.
7. **삭제** — 목록의 항목과 상세 화면에서 저장한 글을 삭제할 수 있다. 삭제 전에 확인을 거치고, 삭제하면 목록에서 사라진다. 상세 화면에서 삭제하면 목록으로 돌아간다.
8. **접근 보호** — 로그아웃 상태에서 `/saved`나 상세 화면 주소를 열면 로그인 화면으로 이동하고, 로그인하면 원래 열려던 화면으로 돌아온다.

저장하는 내용은 제목, 저자(있을 때만), 원문 주소, 도메인, Markdown 본문이다. 사용자가 고른 프롬프트와 직접 입력한 문장은 저장하지 않는다.

## 승인된 범위

- 변환 결과 영역의 저장 버튼과 저장 안내 알림.
- 저장한 글 목록 화면, 상세 화면, 삭제(확인 포함), 빈 상태.
- 메인 화면에서 목록으로 가는 링크.
- 저장한 글을 본인만 읽고 갱신하고 삭제하는 접근 규칙.

## 수용 기준

1. 로그인한 사용자가 변환 후 `저장`을 누르면 저장 완료 알림이 보이고, `/saved`를 열면 그 글이 목록 맨 위에 제목, 도메인, 저장한 날짜와 함께 보인다.
2. 같은 주소를 변환해 다시 `저장`하면 목록에 항목이 하나만 있고(중복 없음), 갱신했다는 알림이 보인다.
3. 새로고침이나 로그아웃 후 다시 로그인해도 저장한 글이 목록에 남아 있다.
4. 목록에서 항목을 열면 상세 화면에 저장해 둔 제목과 렌더링된 본문이 보이고, 복사하기를 누르면 클립보드에 `# 제목`이 맨 앞에 붙은 저장한 Markdown이 들어 있다. .md 다운로드와 ChatGPT·Claude로 열기도 변환 화면과 같은 결과를 낸다.
5. 로그아웃 상태에서 `저장`을 누르면 로그인 안내와 링크가 보이고, 변환 결과는 지워지지 않으며 복사하기가 계속 동작한다.
6. 삭제를 누르면 확인이 보이고, 확인하면 항목이 목록에서 사라진다. 상세 화면에서 삭제하면 목록으로 돌아가고, 삭제한 글의 상세 주소를 다시 열면 찾을 수 없다는 화면이 보인다. 확인을 취소하면 항목이 그대로 남는다.
7. 저장한 글이 하나도 없는 사용자의 `/saved`에는 빈 상태 안내와 변환 화면으로 가는 길이 보인다.
8. 두 사용자 A, B가 각각 글을 저장했을 때, A의 목록에는 A의 글만 보이고, A가 B의 글 상세 주소를 열면 찾을 수 없다는 화면이 보인다. 로그인하지 않은 호출과 다른 사용자의 호출로는 저장한 글을 읽거나 바꾸거나 지울 수 없다.
9. 로그아웃 상태에서 `/saved`와 상세 주소를 열면 로그인 화면으로 이동하고, 로그인 후 원래 화면으로 돌아온다.
10. 좁은 화면(모바일 폭)과 라이트·다크 모드 양쪽에서 저장 버튼, 목록, 상세 화면의 컨트롤이 모두 사용 가능하고 읽힌다.

## 설정된 제약과 근거

- **저장한 글은 본인만 접근한다.** 저장한 글은 사용자가 읽던 글이라 다른 사용자에게 보이면 안 된다. 접근 판단은 서버가 확인한 로그인 사용자 기준으로 하고, 화면 상태만으로 판단하지 않는다. (사용자 요청: "내가 저장한 글")
- **비로그인 저장은 안내만 한다.** 로그인 화면으로 바로 보내면 방금 변환한 결과가 사라지므로, 결과를 지키고 안내만 띄운다. (사용자 확정)
- **삭제를 범위에 넣는다.** 잘못 저장한 글을 정리할 수 없으면 목록이 쌓이기만 한다. (사용자 확정)
- 화면 구성은 [ui-composition](../../decisions/ui-composition.md)을 따른다. 새 의존성은 [dependency-versions](../../decisions/dependency-versions.md)를 따른다.
- 기존 로그인과 `/settings` 동작은 바뀌지 않는다.

## 가정 (덮어쓸 수 있음)

- 같은 사용자가 같은 원문 주소(입력한 그대로, 앞뒤 공백 제외)를 다시 저장하면 새 항목 대신 기존 항목을 갱신한다. 주소의 `www`, 끝 슬래시, 쿼리 차이를 같은 주소로 합치지는 않는다.
- 저장 후 변환 화면에 머문다. 목록으로 자동 이동하지 않는다.
- 목록은 전부 한 화면에 보인다. 페이지 나눔과 검색은 없다.
- 삭제는 되돌릴 수 없고, 휴지통은 없다.
- 새 화면(목록, 상세, 삭제 확인)은 프로토타입 없이 ui-composition 규칙과 기존 변환 화면의 문법(Card, Empty, Alert, 같은 헤더 구성)으로 만든다.
- UI 문구는 한국어다.

## 범위 밖과 이유

- 저장한 글의 수정(제목·본문 편집), 폴더·태그·검색·정렬 변경 — 요구에 없다.
- 다른 사람과 공유하는 링크 — 요구가 "내가 저장한 글"이고 공유는 접근 규칙을 바꾼다.
- 저장하지 않은 변환 결과의 자동 보관(변환 이력) — 사용자가 고른 것만 저장한다.
- 저장한 글의 원문 자동 갱신 — 같은 주소를 다시 변환해 저장하는 것으로 갱신한다.
- 페이지 나눔, 저장 개수 제한, 본문 크기 제한 같은 성능·남용 방어 — 이 템플릿의 검증 예산에서 스펙이 요구하지 않은 하드닝은 범위 밖이다.

## 남은 위험

- 변환한 본문 전체를 저장하므로 긴 글을 많이 저장하면 목록과 저장 공간이 커진다. 목록은 본문 없이 제목·도메인·날짜만 가져오게 하는 것이 구현의 판단 몫이며, 한도와 페이지 나눔은 쓰다가 문제가 보일 때 다룬다.
- 새 화면의 시각 모습은 사전에 사용자가 보고 승인하지 않았다. 구현 후 실제 화면으로 확인하고 어긋나면 고친다.
- 같은 글이 주소 표기만 달라(`www` 유무 등) 중복 저장될 수 있다.
