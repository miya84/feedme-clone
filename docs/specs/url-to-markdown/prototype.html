React 서버 컴포넌트를 1년 동안 써 보고 남기는 메모: 기대와 달랐던 다섯 가지

김도윤 blog.doyun.dev
앞에 붙일 프롬프트 (선택)

열기를 누르면 내용이 클립보드에 복사되고 새 탭에서 새 채팅이 열립니다. 채팅창에 붙여넣기만 하면 됩니다.

작년 이맘때 사내 어드민을 Next.js App Router로 옮기면서 서버 컴포넌트를 본격적으로 쓰기 시작했습니다. 1년이 지난 지금, 처음 기대와 실제가 어디서 달랐는지 정리해 둡니다.

좋았던 점

  • 데이터를 가져오는 코드가 화면 바로 옆에 있습니다. API 라우트를 하나 더 만들고 useEffect로 부르던 단계가 사라졌습니다.
  • 번들 크기가 눈에 띄게 줄었습니다. 날짜 포맷 라이브러리(약 72KB)가 클라이언트에서 빠진 것만으로 첫 로딩이 0.4초 빨라졌습니다.
  • 권한 검사를 서버에서 끝내니, 보였다가 사라지는 메뉴가 없어졌습니다.

예상보다 힘들었던 점

가장 많이 헷갈린 건 "이 컴포넌트가 지금 어디서 실행되는가"였습니다. 'use client'를 붙인 파일이 가져오는 모든 모듈이 클라이언트 번들로 들어간다는 사실을 팀원 절반이 한 번씩 놓쳤습니다.

경계를 파일 단위로 생각하지 말고, import 그래프 단위로 생각해야 합니다.

캐시를 끄는 습관

처음 석 달 동안 "데이터가 안 바뀐다"는 버그 신고는 대부분 캐시 때문이었습니다. 지금은 아래처럼 캐시 정책을 명시하는 것을 규칙으로 둡니다.

const orders = await fetch(`${API}/orders?status=pending`, {
  cache: "no-store",
});

다시 시작한다면

  1. 클라이언트 컴포넌트는 트리의 끝(잎)에만 둡니다.
  2. 서버 전용 모듈에는 server-only를 import해서 실수로 클라이언트에 끌려가는 일을 막습니다.
  3. 캐시 정책은 페이지마다 주석으로 남깁니다.

더 자세한 마이그레이션 기록은 사내 어드민 이전기에 있습니다.
